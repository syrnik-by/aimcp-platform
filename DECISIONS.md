# Журнал решений

Формат записи: дата, решение, причина, отвергнутые варианты, что менять при переносе в корпоративный контур.

## D-001. Среда прототипа — одна Windows-машина
Дата: 2026-10-12
- Решение: Ollama стоит на Windows напрямую, инфраструктура (Postgres и далее) — в Docker, приложения запускаются на хосте через Gradle.
- Причина: Ollama напрямую получает доступ к GPU, приложения на хосте проще отлаживать.
- Отвергнуто: приложения в контейнерах; локальный GitLab CE (не хватит ОЗУ рядом с моделью на 18 ГБ).
- Перенос: все адреса и имена контейнеров — в конфигурации.

## D-002. Java 17, Gradle 7.3.3, граница по дате 20.02.2022
Дата: 2026-10-12
- Решение: Java 17 (Liberica 17.0.10), Gradle wrapper 7.3.3. Библиотеки не новее 20.02.2022, правило действует и на транзитивные зависимости. Исключения только по согласованию с пользователем. Проверка дат — вручную по Maven Central.
- Причина: во внутреннем репозитории артефактов нет более новых версий; проверить наличие версий в нём нельзя.
- Отвергнуто: Java 21, Spring Boot 3.x (jakarta.*).
- Перенос: на корпоративной машине версию Gradle подтверждает пользователь. В системе `JAVA_HOME` указывает на JDK 11: сам Gradle работает на нём, а компиляция и тесты идут на тулчейне 17 (см. D-009).

## D-003. Модели по ролям
Дата: 2026-10-12
- Решение: роль heavy — qwen3-coder:30b, light — qwen2.5:7b, embedding — bge-m3 (1024). Имена моделей и размерность — только в конфигурации. В схеме БД vector(1024); смена модели эмбеддингов означает пересоздание колонки и полную переиндексацию. Эндпоинт эмбеддингов — /api/embed. num_ctx задаётся явно, от 32k.
- Отвергнуто: llama3.2:3b (слабее на русском), deepseek-r1:7b (нет вызова инструментов), nomic-embed-text (768 измерений, не выбран).
- Перенос: роли и имена моделей на корпоративной платформе — в конфигурации.

## D-004. Абстракция модели
Дата: 2026-10-12

## D-009. Java 17 через тулчейн Gradle
Дата: 2026-10-12
- Решение: в сборке `java { toolchain { languageVersion = 17 } }`. Сам Gradle запускается на любой JDK, на которой стартует (у пользователя это 11), компиляция и тесты идут на 17. Расположение JDK 17 задаётся в пользовательском `~/.gradle/gradle.properties` (`org.gradle.java.installations.paths`), в репозитории путей нет. Автоскачивание JDK выключено.
- Причина: у пользователя много проектов на разных JDK, глобальная подмена `org.gradle.java.home` сломала бы их.
- Отвергнуто: `org.gradle.java.home`; запуск Gradle только на 17.
- Перенос: PORTING: на корпоративной машине нужна JDK 17, доступная тулчейну (при необходимости — то же пользовательское свойство).

## D-010. Адрес репозитория артефактов — свойство
Дата: 2026-10-12
- Решение: репозиторий в сборке берётся из свойства `mavenRepoUrl` (`gradle.properties`), а не из `mavenCentral()`. То же для репозитория плагинов (`pluginManagement` в `settings.gradle`) к шагу 0.3.
- Причина: правило переносимости — адреса не в коде; во `frame` и `adapter` сделано так же.
- Перенос: PORTING: в корпоративном контуре `mavenRepoUrl` переопределяется в `~/.gradle/gradle.properties`; `distributionUrl` в `gradle/wrapper/gradle-wrapper.properties` заменяется на внутреннее зеркало.

## D-012. Spring Boot 2.6.3, MVC, версии через platform
Дата: 2026-10-12
- Решение: Spring Boot 2.6.3, веб-слой на Spring MVC (`spring-boot-starter-web`). Версии берутся из BOM через `platform(...)` Gradle, плагин `io.spring.dependency-management` не подключаем (он приходит транзитивно только в classpath плагина Boot). Версия Boot — одно свойство `springBootVersion`.
- Причина: 2.6.4 вышел 2022-02-24, за границей 2022-02-20; MVC проще, потоковые ответы чата возможны и на нём.
- Отвергнуто: Spring Boot 2.6.4 и выше; WebFlux; свой сервер на `com.sun.net.httpserver`.
- Перенос: PORTING: адрес репозитория плагинов и артефактов — свойство `mavenRepoUrl`.

## D-014. Проверка дат зависимостей — вручную, без задачи в сборке
Дата: 2026-10-13
- Решение: задачу Gradle `checkDependencyDates` не делаем. При подключении каждой зависимости Claude проверяет даты всей цепочки (runtime, compile, test, `buildEnvironment`) по дате .pom на Maven Central и записывает итог в DEPENDENCIES.md. Скрипты проверки — вне репозитория.
- Причина: задача раздувает корневой `build.gradle`, пользователь считает её излишней.
- Отвергнуто: задача Gradle с HEAD-запросами к Maven Central; отдельный скрипт в репозитории.
- Перенос: на корпоративной машине проверка не нужна — во внутреннем репозитории только допустимые версии.
