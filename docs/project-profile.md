# Контракт профиля проекта, версия 1

## Назначение

Профиль проекта — файл `at-profile.yaml` в репозитории проекта тестов. Агент-исполнитель на ВМ один на все проекты, различия между системами (как запускать тесты, что можно выносить в тех.зону, что маскировать) выносятся в профиль. Файл лежит в репозитории, поэтому меняется через ревью и виден владельцам ИС. Профиль — политика данных: от него зависит, уйдут ли логи и стектрейсы с ВМ наверх, поэтому загрузка строгая.

В профиль входит только то, что читают шаги этапа 2. Остальное добавляется, когда появляется код, который это читает (см. «Вне версии 1»).

## Общие правила

1. **Один файл, `at-profile.yaml`, в корне репозитория проекта тестов.** Путь к файлу агент-исполнитель получает настройкой, а не из кода. Корень файла — словарь: пустой файл или список — ошибка.
2. **Кодировка** UTF-8 (BOM допустим), размер не более 64 КБ (проверяется до разбора). Слишком глубокая вложенность — ошибка.
3. **Закрыто по умолчанию.** Любая ошибка означает, что профиль не загружен, агент-исполнитель не выполняет инструменты. «Частично верного» профиля нет: пропущенное правило маскирования хуже, чем остановка.
4. **Неизвестный ключ на любом уровне — ошибка.** В отличие от файла результатов, где лишние поля игнорируются, здесь опечатка (`data_polcy`) молча отключила бы маскирование.
5. **Повторяющийся ключ — ошибка.** Иначе второй `mask:` тихо затёр бы первый.
6. **Типы строгие, приведения нет.** `restricted: "true"` — ошибка. Версии пишутся в кавычках: `framework_ver: 1.10` YAML прочтёт числом 1.1. Слова `yes`, `no`, `on`, `off` YAML 1.1 читает как булевы значения: элемент `owners: [no]` станет ошибкой типа, булевы значения пишем только `true` и `false`. Ключ без значения (`owners:`) YAML читает как `null`, это тоже ошибка типа: пишем `[]` или убираем ключ.
7. **Теги YAML** (`!!...`) кроме стандартных типов не принимаются: файл из репозитория не должен создавать произвольные классы.
8. **Секреты в профиль не пишем.** Файл в репозитории. Ссылка `repo` вида `http(s)://user:pass@host` (с логином или паролем) — ошибка.
9. **Версия** — `profile_version`, обязательна. Неизвестная версия — ошибка (в файле результатов такой файл пропускается, здесь пропуск означал бы работу без политики данных). Новый ключ означает новую версию, но пока профилей в проектах нет, v1 дополняется на месте.
10. **Сообщения об ошибках** содержат путь к полю в формате JSON Pointer (`/run/command: ...`) и условие, но не значения: профиль не должен попадать в журнал случайно. Исключение — имя неизвестного ключа: оно называет место ошибки, поэтому попадает в сообщение, но обрезанное до 40 символов и без управляющих символов.

## Пример

Файл `docs/examples/at-profile.yaml`:

```yaml
profile_version: 1
project: demo-is
repo: https://ahcode.example.invalid/group/demo-tests.git
framework_ver: "2.4.1"
testit:
  project_id: "00000000-0000-0000-0000-000000000000"
  adapter_ver: "1.2.8"
run:
  command: [gradle, testInTest, "-Pstand=test"]
  timeout: PT45M
env:
  restricted: false
data_policy:
  mask:
    - 'Bearer\s+[A-Za-z0-9._~+/=-]+'
    - '\b\d{16}\b'
  never_send:
    - "secrets/**"
    - "**/*.pem"
owners: [team-qa-demo]
```

## Поля: корень

| Ключ | Тип | Обязательно | Правила |
|---|---|---|---|
| `profile_version` | целое | да | сейчас `1` |
| `project` | строка | да | идентификатор ИС: `[A-Za-z0-9._-]`, длина 1–100. Он же `{project}` в адресе приёма результатов тех.зоны (`/api/projects/{project}/results`) и ключ истории прогонов |
| `repo` | строка | да | ссылка на репозиторий проекта тестов в ahcode, не пустая |
| `framework_ver` | строка | нет | версия фреймворка, в кавычках |
| `testit` | объект | нет | см. ниже |
| `run` | объект | да | см. ниже |
| `env` | объект | да | см. ниже |
| `data_policy` | объект | нет | нет блока — как пустой блок |
| `owners` | список строк | нет | ответственные за профиль: логины или группы в ahcode, строки не пустые. Нет — пустой список |

## Поля: блок `testit`

| Ключ | Тип | Обязательно | Правила |
|---|---|---|---|
| `project_id` | строка | нет | идентификатор проекта в TestIT |
| `adapter_ver` | строка | нет | ожидаемая версия адаптера, в кавычках |

## Поля: блок `run`

| Ключ | Тип | Обязательно | Правила |
|---|---|---|---|
| `command` | список строк | да | команда запуска как **список аргументов**, а не строка для оболочки; не пустой, элементы не пустые. Стенд (профиль Spring), отбор по тегам и остальные параметры Gradle записаны в самой команде, как в CI проекта. Подстановок нет: команда запускается как есть |
| `timeout` | строка | нет | длительность ISO-8601 (`PT45M`), больше нуля и не более `PT12H`. Нет — `PT1H` |

Команда запускается в корне репозитория проекта тестов, без оболочки.

## Поля: блок `env`

| Ключ | Тип | Обязательно | Правила |
|---|---|---|---|
| `restricted` | булево | **да, без значения по умолчанию** | `true` — логи и стектрейсы остаются на ВМ, `false` — после маскирования уходят в тех.зону. Значение для каждой ИС согласует ИБ, поэтому молчаливого значения нет |

## Поля: блок `data_policy`

| Ключ | Тип | Обязательно | Правила |
|---|---|---|---|
| `mask` | список строк | нет | регулярные выражения `java.util.regex`, не более 100 штук по 500 символов. Должны компилироваться и не находить совпадение в пустой строке (иначе маскируется всё). Применяются поверх общего базового списка (`docs/masking-rules.md`): заменяется всё совпадение, а если в выражении есть именованная группа `(?<secret>...)`, то только она |
| `never_send` | список строк | нет | glob-шаблоны путей от корня репозитория (синтаксис `glob` из `java.nio.file`), не более 100 штук. Только относительные пути с `/`, без `..`. Файлы по этим путям агент-исполнитель не читает и не отдаёт никогда |

## Кто что использует

| Часть профиля | Где применяется | Шаг |
|---|---|---|
| `data_policy.mask` | маскирование на ВМ до отправки | 2.2 |
| `data_policy.never_send` | чтение логов и файлов | 2.4–2.6 |
| `run` | запуск тестов (`run_tests`) | 2.5 |
| `env.restricted` | что можно отдать тех.зоне | 2.6 |
| весь профиль | инструмент `get_profile` | 2.4 |

## Вне версии 1

Намеренно не вошло, добавим, когда появится код, который это читает:

- **Выбор стенда и тегов агентом** (`run_tests` с параметрами): подстановки в `command` и список допустимых стендов. Решается в шаге 2.5, когда станет ясно, как проекты принимают стенд (свойство Gradle → профиль Spring) и теги (`includeTags`, `cucumber.filter.tags`). Список тегов проекта даст `get_test_inventory` (2.4), вручную в профиле его не ведём.
- **Адреса стендов и `healthcheck`.** Адреса уже лежат в `application-*.properties` проекта, второй источник разошёлся бы с первым. Вернёмся, когда будет делаться `check_env` (2.4), если окажется, что брать адрес больше неоткуда.
- **Диспетчер исполнителей** (этап 10): блок `runners` (адрес, метки, `max_parallel`), у стенда блокировка `lock`.
- Переменные окружения и рабочий каталог запуска.
- Общий профиль с наследованием для нескольких проектов.
- Перечитывание профиля без перезапуска агента-исполнителя (сейчас читается при старте).
- Проверка подлинности профиля (подпись, хэш из тех.зоны).
