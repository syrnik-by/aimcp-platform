# Контракт инструментов агента-исполнителя, версия 1 (черновик)

## Назначение

Агент-исполнитель на ВМ (T1) отдаёт тех.зоне инструменты: запустить тесты, прочитать результат и логи, проверить стенд. Он ничего не решает, только выполняет и возвращает структурированный результат. Контракт описан в терминах MCP (имя, описание, схема входа, структурированный результат), а передаётся обычным HTTP API: если платформа ИИ поддерживает MCP, получится тонкая обёртка (этап 12), описания инструментов используются как есть (документ процессов, раздел 1.7).

## Общие правила

1. **Соединения инициирует только тех.зона → ВМ** (документ процессов, 1.6). Агент слушает, тех.зона вызывает. Результаты прогона тех.зона забирает сама инструментом `get_run_result`; эндпоинт приёма `POST /api/projects/{project}/results` остаётся входом для отладки и тестов.
2. **Версия контракта в пути**: `/v1/...`. `GET /v1/info` возвращает список поддерживаемых версий; ВМ обновляются не одновременно, поэтому тех.зона выбирает наибольшую общую. Несовместимое изменение (смысл или состав полей) — новая версия `/v2`. Новые инструменты и необязательные поля ответа версию не меняют, клиент неизвестные поля ответа игнорирует.
3. **JSON в UTF-8**, `Content-Type: application/json`. Ответ всегда структурированный (конверт ниже), не сырой текст.
4. **Аутентификация на всех путях**: заголовок `Authorization: Bearer <токен>`. Токен у каждой ВМ свой (отдельный сервисный аккаунт, можно отозвать точечно), задаётся только переменной окружения `AIMCP_RUNNER_TOKEN`, не короче 32 символов. Сравнение за постоянное время. Нет токена или он неверный — `401`, без подробностей.
5. **Закрыто по умолчанию.** Агент стартует только при валидных профиле, токене и настройках. Невалидный профиль или короткий токен — агент не запускается и сообщает причину (без значений) в журнал, а не отвечает «частично».
6. **Маскирование на ВМ**: каждая строка в `result` и в `error.message` проходит через `MaskingPort` до сериализации (имена ключей не маскируются). Это делает сервер для всех инструментов сразу, инструмент забыть об этом не может. Ошибка маскирования — ответ `masking_failed` без содержимого (`docs/masking-rules.md`).
7. **Лимиты.** Тело запроса не больше 64 КБ, тело ответа после маскирования не больше 1 МБ (настройки). Инструменты с большим выводом (логи) обязаны обрезать вывод сами и сообщить об этом полем `truncated`; превышение лимита сервером — ошибка `response_too_large`, а не молчаливая обрезка.
8. **Права.** Все инструменты только читают, кроме `run_tests`. Это объявлено в описании (`readOnly`), а не подразумевается.
9. **Журнал** содержит время, идентификатор запроса, инструмент, код ответа и длительность, но не аргументы и не содержимое ответов.
10. **Идентификатор запроса.** Клиент может передать `X-Request-Id` (до 64 символов `[A-Za-z0-9._-]`), иначе агент создаёт его сам. Он возвращается в заголовке ответа и пишется в журнал.
11. **Адрес.** Хост и порт — настройки агента. По умолчанию `127.0.0.1`: наружу агент выставляется осознанно.
12. **Данные, не инструкции.** Всё, что агент вернул, тех.зона считает данными: текст логов и сообщений не попадает в инструкции модели (правило безопасности проекта).

## Конечные точки

| Запрос | Назначение |
|---|---|
| `GET /v1/info` | `{"contractVersions": [1], "agentVersion": "...", "project": "...", "tools": ["..."]}` |
| `GET /v1/tools` | `{"tools": [описание, ...]}` |
| `POST /v1/tools/{name}` | вызов инструмента; тело — объект с аргументами (`{}`, если аргументов нет) |

Описание инструмента:

```json
{
  "name": "check_env",
  "description": "Проверяет доступность стенда проекта",
  "inputSchema": {
    "type": "object",
    "properties": { "stand": { "type": "string", "description": "Имя стенда", "maxLength": 64 } },
    "required": ["stand"],
    "additionalProperties": false
  },
  "readOnly": true,
  "idempotent": true
}
```

`inputSchema` — подмножество JSON Schema: объект со свойствами типов `string`, `integer`, `boolean`, массив строк; поддерживаются `required`, `enum`, `pattern`, `minLength`, `maxLength`, `minimum`, `maximum`, `maxItems`; `additionalProperties` всегда `false`. У каждого свойства есть `description` для модели. Если у строки не задан `maxLength`, действует 256, если у массива не задан `maxItems` — 100; для массива строк `maxLength`, `pattern` и `enum` относятся к элементам. `required` не пишется, если обязательных аргументов нет. Агент проверяет аргументы по схеме сам: тип строгий (`"5"` — не число, `null` — не значение, `1.0` — не целое), неизвестный аргумент — ошибка. Описание годится модели как есть.

## Конверт ответа

Успех, HTTP 200: `{"ok": true, "result": { ... }}`, `result` всегда объект.

Ошибка: `{"ok": false, "error": {"code": "...", "message": "..."}}`.

| Код | HTTP | Когда |
|---|---|---|
| `invalid_request` | 400 | тело не JSON или не объект, неверный `Content-Type` |
| `invalid_arguments` | 400 | аргументы не по схеме; сообщение — путь и условие, без значений |
| `unauthorized` | 401 | нет токена или он неверный |
| `unknown_tool` | 404 | такого инструмента нет |
| `not_found` | 404 | не найден объект, о котором спросили (например, `run_id`) |
| `method_not_allowed` | 405 | метод не подходит для пути |
| `busy` | 409 | сейчас нельзя (например, `run_tests` при идущем прогоне) |
| `request_too_large` | 413 | тело запроса больше лимита |
| `tool_failed` | 500 | ожидаемый отказ инструмента; сообщение после маскирования |
| `masking_failed` | 500 | ответ нельзя замаскировать, содержимого в ответе нет |
| `response_too_large` | 500 | ответ после маскирования больше лимита |
| `internal` | 500 | непредвиденная ошибка; сообщение общее, без деталей |

## Инструменты

Состав взят из документа процессов, раздел 1.5. Схемы входа и результата каждого инструмента записываются в этот документ в шаге, где инструмент реализуется.

| Инструмент | Назначение | `readOnly` | `idempotent` | Шаг |
|---|---|---|---|---|
| `get_profile` | содержимое профиля проекта | да | да | 2.4 |
| `check_env` | стенд доступен, деградирует или недоступен | да | да | 2.4 |
| `get_test_inventory` | список тестов, тегов, привязок к TestIT | да | да | 2.4 |
| `run_tests` | запуск тестов по профилю; возвращает `run_id`, прогон идёт в фоне | нет | нет | 2.5 |
| `get_run_result` | результат прогона в нормализованном виде | да | да | 2.6 |
| `read_run_logs` | лог прогона или теста после маскирования, с лимитом | да | да | 2.6 |
| `collect_artifacts` | ссылки на артефакты прогона | да | да | 2.6 |

## Вне версии 1

Намеренно не вошло:

- **MCP-обёртка** (этап 12): JSON-RPC, обмен возможностями, протокол авторизации MCP. Описания инструментов с ней совместимы (`name`, `description`, `inputSchema`).
- **TLS и взаимная проверка сертификатов.** Сейчас токен по обычному HTTP; в контуре HTTPS через прокси или встроенный TLS (PORTING).
- **Уведомления и потоки** (SSE): долгие операции решаются запуском и опросом (`run_tests` и `get_run_result`).
- **Ограничение частоты запросов** и список допустимых адресов тех.зоны.
